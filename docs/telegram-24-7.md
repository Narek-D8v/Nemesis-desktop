# Немуся в Telegram 24/7

Бот умеет работать без окна: `python -m nemus --telegram`. Это отдельный
headless-процесс, который поднимает long polling и живёт, пока живёт процесс.
Так его можно держать на ноутбуке при закрытом приложении или на постоянном
хосте, который не выключается.

## Сначала важное: где работает бот, там и инструменты

Бот — это не «пульт» к ноутбуку. Инструменты (`read_file`, `run_shell`,
`open_application`, `see_screen`, Spotify и т.д.) выполняются **на той машине,
где запущен процесс бота**:

| Где запущен бот | Что он видит и умеет |
|---|---|
| Ноутбук с Windows | Все файлы, программы, экран, буфер обмена, Spotify |
| VPS/контейнер | Только файлы и команды сервера; экран/окна ноутбука недоступны |
| Raspberry Pi дома | Файлы Pi и команды в его сети; ноутбук — только по сети (SSH/WoL) |

Поэтому «бот на VPS» и «управление выключенным ноутбуком» — взаимоисключающие
вещи. Ниже — два честных сценария.

## Сценарий A. Ноутбук включён, приложение закрыто

Это то, что делает «Связь с Windows»: фоновая служба работает, пока включён
компьютер. Бот можно поднять отдельно от GUI и автозапускать при входе.

1. Проверь конфиг:

   ```bash
   python -m nemus --telegram --check
   ```

   Должно быть `telegram.enabled: true`, токен и хотя бы один ID в
   `telegram.allowed_users`.

2. Включи автозапуск. Это можно сделать в приложении:
   **Настройки → Telegram → Демон без окна → «Запускать Telegram-бота при
   входе в Windows»**, затем «Сохранить». Галочка отражает реальное
   состояние автозапуска: задача `NemusTelegram` **и** ярлык в папке
   «Автозагрузка».

   Либо зарегистрируй задачу вручную (PowerShell, без админа):

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install_telegram_autostart.ps1
   ```

   В «Автозагрузке» Windows появляется ярлык **«Немуся Telegram»**. При
   входе он скрыто запускает задачу `NemusTelegram`, а та поднимает
   `pythonw -m nemus --telegram` и перезапускает процесс при падении.
   Консольного окна нет, логи — в файле из `logging.file` (по умолчанию
   `data/nemus.log`).

   Если автозапуск включали в старой версии, задача могла остаться без
   ярлыка: выключи и снова включи галочку, чтобы создать его.

   Внутри процесса тоже есть сторож: раз в 5 секунд проверяется, жив ли
   поток polling, а раз в минуту — отвечает ли Bot API. Если polling умер,
   бот сначала пытается поднять его на месте, не завершая процесс и не
   теряя задачу. Если Telegram недоступен дольше 3 минут, бот
   перезапускается целиком внутри процесса. Task Scheduler остаётся
   страховкой на случай падения самого процесса. Ошибки сторонних
   библиотек (telegram, httpx) пишутся в тот же файл, а не теряются без
   консоли.

3. Удалить автозапуск можно той же галочкой в настройках или вручную:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install_telegram_autostart.ps1 -Uninstall
   ```

Важно: Telegram разрешает только один `getUpdates` на токен. Если запущены и
GUI, и автозапуск, второй процесс вежливо откажется стартовать (файл-замок
`data/telegram.lock`) и напишет об этом в лог. Оставь что-то одно.

Если всё же нужно держать GUI и headless одновременно, база у них общая:
SQLite работает в WAL-режиме и ждёт освобождения записи до 30 секунд, а
одновременная миграция старой схемы безопасна. Это не делает SQLite
многописательным — записи по-прежнему идут по очереди, — но убирает
`database is locked` при коротких операциях.

Чтобы ноутбук не засыпал при закрытой крышке (питание от сети):

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0
powercfg /setactive SCHEME_CURRENT
```

Это меняет системные настройки питания — применяй осознанно. Если ноутбук
всё равно выключен или спит, бот на нём работать не будет: это ограничение
железа, а не приложения.

## Сценарий B. Ноутбук выключен — бот на постоянном хосте

Подойдёт любой VPS/VDS с Docker (1 vCPU, 1–2 ГБ RAM достаточно), Raspberry Pi
или старый мини-ПК. Бот будет отвечать всегда, но работать с файлами хоста,
а не ноутбука. Для задач «скачай, посчитай, собери отчёт, отправь файл» этого
хватает; для «открой программу на ноутбуке» — нет.

### Docker

```bash
cp .env.telegram.example .env.telegram
# заполни токен, allowed_users и ключ модели
docker compose -f docker-compose.telegram.yml up -d --build
docker compose -f docker-compose.telegram.yml logs -f
```

Проверка статуса:

```bash
docker compose -f docker-compose.telegram.yml ps
docker inspect --format '{{.State.Health.Status}}' nemus-telegram
```

`HEALTHCHECK` смотрит на heartbeat `data/telegram.health`, который бот
обновляет каждые 5 секунд, — одного `--check` недостаточно, он проверяет
только конфиг. Если polling/поток умер, сторож сначала восстанавливает
polling на месте, а после 3 минут простоя перезапускает бота внутри
процесса. `restart: unless-stopped` остаётся страховкой на случай падения
самого процесса. Если завис весь процесс и heartbeat протух, healthcheck
пометит контейнер `unhealthy`; Docker сам по себе unhealthy не
перезапускает, поэтому основной механизм — сторож внутри процесса.

Heartbeat можно проверить вручную:

```bash
docker compose -f docker-compose.telegram.yml exec nemus-telegram \
  python -m nemus --telegram --health
```

Остановка/обновление:

```bash
docker compose -f docker-compose.telegram.yml down
git pull
docker compose -f docker-compose.telegram.yml up -d --build
```

История, рабочая папка и логи лежат в `./data` на хосте и переживают
пересборку. Секреты — только в `.env.telegram` (он в `.gitignore`).

### Без Docker (systemd на Linux)

```ini
# /etc/systemd/system/nemus-telegram.service
[Unit]
Description=Nemus Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/nemus
EnvironmentFile=/opt/nemus/.env.telegram
ExecStart=/opt/nemus/venv/bin/python -m nemus --telegram
Restart=always
RestartSec=5
# watchdog внутри процесса завершает его при смерти polling,
# systemd поднимает снова
User=nemus

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now nemus-telegram
journalctl -u nemus-telegram -f
```

## Ограничения headless-режима

- Нет GUI, голосового ввода с микрофона и realtime-режима.
- Голосовые сообщения в Telegram по умолчанию распознаются облачным Gemini
  (`gemini-3.5-transcribe`): нужен ключ Gemini и интернет, зато не нужны
  `faster-whisper`, модель и ffmpeg — OGG/Opus уходит в API напрямую. Если
  ключа Gemini нет или он не сработал, пробуется OpenAI; затем локальный
  faster-whisper (тогда нужны пакет и скачанная модель; в лёгком Docker-образе
  их нет). Принудительно: `voice.stt.engine: gemini | openai | faster-whisper`.
- Генерация изображений работает без кредитов через бесплатный Pollinations:
  текст→картинка, а для фото — приближённая чиби/стилизация по описанию
  (Gemini описывает фото, Pollinations рисует). Точное сохранение лица дают
  только провайдеры с кредитами (Gemini/OpenRouter/OpenAI); они выбираются
  автоматически или через `images.provider`.
- Инструменты экрана/мыши/буфера обмена на Linux-сервере вернут ошибку —
  это нормально, они для Windows-машины с рабочим столом.
- Для видео-кружков нужен `ffmpeg` (в Docker-образе уже есть).
- Ключи из OS keyring на сервере недоступны — передавай их переменными
  окружения (`NEMUS_LLM__PROVIDERS__...__API_KEY`).

## Команды без зубрёжки

`/help` — не простыня текста, а каталог: четыре категории, у каждой команды
описание, синтаксис, разбор аргументов и готовый пример. `/help read` сразу
открывает карточку `/read <url> [вопрос]` и объясняет, что такое `<url>` и
`[вопрос]`. Кнопка «📚 Команды» есть на стартовом экране. Переходы между
категориями и карточками редактируют одно и то же сообщение.

Если написать неизвестную команду, бот предложит похожие и даст кнопки.
Обычные фразы тоже работают: «прочитай этот сайт», «что с компьютером?»,
«запусти это в фоне» — агент сам выберет инструмент.

## Команды диагностики, документы и фоновые задачи

- `/pc` — загрузка CPU, RAM, swap, диски, батарея, аптайм и топ-5 процессов
  по памяти (на базе `psutil`).
- `/doctor` — самодиагностика: работает ли polling, поднят ли Web App,
  получен ли URL Cloudflare-туннеля, задан ли ключ выбранного LLM-провайдера,
  сколько MCP-серверов включено, сколько свободно на диске и последние
  `ERROR`/`WARNING` из `logging.file`. Токен и ключи не печатаются.
- `/read URL [вопрос]` — читает страницу с SSRF-защитой: заголовок, meta
  description, структуру заголовков, основной текст и до 30 ссылок. Без
  вопроса присылает разбор, с вопросом — передаёт страницу агенту.
- Документы с подписью (PDF, DOCX, PPTX, XLSX, CSV, HTML, TXT/MD и код)
  автоматически превращаются в текст и добавляются к задаче. PDF читает
  `pypdf`, офисные форматы — стандартный `zipfile`, поэтому отдельный Office
  не нужен. Сканы без текстового слоя не распознаются: пришлите их как фото.
- `/run команда` — запускает долгую команду в рабочей папке, `/jobs` —
  список, `/log ID [строк]` — хвост вывода, `/kill ID` — остановка вместе с
  дочерними процессами. По завершении бот присылает код возврата и последние
  15 строк вывода. Команды выполняются от имени пользователя бота — не
  запускайте бота с root на VPS и не давайте доступ посторонним.

## Проактивный автопилот

Автопилот — это фоновый watcher, а не отдельный бот. Он запускается и в GUI,
и в Telegram-демоне; события складываются в общий SQLite
(`autopilot.state_db`), поэтому два процесса не пришлют одно уведомление
дважды.

Поддерживаемые триггеры:

| trigger | что делает |
|---|---|
| `file_created` | новый файл по glob-пути |
| `file_modified` | изменился mtime/размер файла |
| `log_error` | новая строка, подходящая под regex |
| `schedule` | ежедневно `at: "09:00"` или каждые `interval_minutes` |
| `disk_low` | занятость диска выше `threshold`% |
| `battery_low` | батарея ниже `threshold`% и не заряжается |

Пример правила:

```yaml
autopilot:
  enabled: true
  rules:
    - id: "new-invoice"
      trigger: "file_created"
      path: "data/workspace/Downloads/*.pdf"
      message: "Новый PDF: {name}"
      prompt: "Разбери документ {path}: сумма, дата, что оплатить"
      auto_run: true
      cooldown_minutes: 30
```

`auto_run: true` запускает обычную агентскую задачу; результат придёт в чат
(или в окно GUI, если событие забрал GUI). `auto_run: false` — только
уведомление. Частота ограничена `max_notifications_per_hour`, ночью действуют
`quiet_hours_start/end`. Управление: `/auto`, `/auto on|off`, `/auto rules`,
`/auto events`, `/auto check`.

## Самовосстановление

Self-healing следит за `logging.file` и считает одинаковые ошибки
(нормализует цифры, адреса и id). После `error_threshold` повторов за
`window_minutes` создаётся инцидент:

1. сохраняется контекст лога и файлы из traceback;
2. LLM предлагает минимальный unified diff;
3. патч проверяется на безопасные пути и `git apply --check`;
4. `/heal apply ID` создаёт резервные копии, применяет diff и запускает
   `healing.test_command`;
5. при ненулевом коде файлы автоматически восстанавливаются, инцидент
   получает статус `failed`;
6. `/heal rollback ID` откатывает уже применённый патч.

Команды: `/heal`, `/heal show ID`, `/heal apply ID`, `/heal reject ID`,
`/heal rollback ID`, `/heal scan`, `/heal on|off`. Автоприменение
(`auto_apply: true`) существует, но по умолчанию выключено: это изменение
кода на работающей машине.

## Голосовой компаньон

В GUI включите `voice.companion.enabled`. После слова активации Немуся
говорит `wake_ack`, слушает продолжение и при паузе длиннее
`follow_up_seconds` возвращается в режим wake word. `speak_events` разрешает
озвучивать события автопилота, а `quiet_hours_start/end` не дают говорить
ночью. Перебивание голосом работает при `voice.barge_in: true`.

## Живой ответ

В личке бот использует возможности Bot API 10.3/10.4, если сервер их
поддерживает. Живой ответ, rich-сообщения и ephemeral включаются галочкой
«Живой ответ и rich-сообщения» (`telegram.advanced_ui`). Если выключить
`advanced_ui`, поведение в точности прежнее: одно редактируемое сообщение
прогресса и обычный ответ.

- **Нативный стрим и «Стоп».** В личке ответ печатается прямо в черновике,
  под ним есть кнопка остановки. Черновик обновляется раз в 1,5 секунды, а
  раз в 10 секунд повторяется, чтобы не истечь на долгом инструменте.
  Кнопка «Стоп» останавливает текущую задачу, а не бота: частичный ответ
  сохраняется, история остаётся валидной. `/stop` по-прежнему выключает
  самого бота.
- **Rich-ответы.** Финальный текст уходит сообщением с заголовками, списками,
  таблицами и кодом, плюс кнопки «Повторить / Новый диалог / Помощь». Длинные
  цитаты сворачиваются в раскрывающийся блок Bot API 10.3, чтобы не занимать
  весь экран. HTML из ответа модели не исполняется: теги экранируются, кнопки
  добавляет только бот. Если rich-сообщение не принято или текст длиннее
  32 768 символов, тот же ответ приходит обычными HTML-сообщениями.
- **Настройки в Telegram Mini App.** `/panel` присылает кнопку, которая
  открывает Web App с разделами «Модель», «Голос», «Характер», «Авто»,
  «Каналы», «Инструменты» и «О программе»: LLM, голос и TTS, характер,
  автопилот и self-healing, Telegram, Spotify, инструменты, MCP и скиллы.
  Переключатели, выборы, числовые поля, текстовые значения и секреты меняются
  прямо в Mini App. Изменения сразу пишутся в `config/config.yaml`; модель,
  инструменты и токен бота применяются после перезапуска процесса.

  В разделе LLM модель выбирается не на память: поле «Модель» открывает
  живой каталог провайдера с поиском, бейджами FREE/PAID и кнопкой
  обновления. Для `llama_cpp` там же видны локальные `.gguf`. Ниже — панель
  Hugging Face: поиск GGUF-репозиториев, выбор файла, скачивание с прогрессом
  и отменой, затем «Сделать активной» (прописывает провайдера, модель и
  `model_path`). Поиск и скачивание идут через бота, поэтому браузер не
  требует токена Hugging Face; для gated-моделей задайте `HF_TOKEN` в
  окружении процесса.

  Панель «Локальные GGUF» показывает готовые и недокачанные файлы. Готовую
  модель можно сделать активной или удалить; недокачанный `.part` —
  продолжить (источник хранится рядом в `.part.json`, а для старых файлов
  берётся из `llm.llama_cpp.hf_repo/hf_file`) или удалить. Активную модель
  удалить нельзя, пока не выбрана другая. Докачка использует HTTP Range и
  продолжает с текущего размера `.part`.

  Локальный сервер Mini App поднимается вместе с ботом на
  `telegram.web_app_host:telegram.web_app_port` (по умолчанию
  `127.0.0.1:8765`). Если `telegram.web_app_url` не задан, Немуся сама
  запускает Cloudflare Quick Tunnel:

  ```text
  cloudflared tunnel --url http://127.0.0.1:8765 --no-autoupdate
  ```

  Она читает из вывода `https://….trycloudflare.com` и сразу подставляет его
  в кнопку `/panel`; аккаунт Cloudflare и токен не нужны. Если в меню бота
  уже включена Web App-кнопка, бот обновляет и её на новый адрес. Старые
  сообщения с кнопкой могут хранить прежний URL — после перезапуска вызови
  `/panel` заново. Зависший туннель, чей публичный адрес перестал отвечать,
  перезапускается автоматически. При первом запуске
  `cloudflared` скачивается в `data/bin` (флаг
  `telegram.web_app_tunnel_download`, отключение — `web_app_tunnel: false`).
  Пока туннель поднимается, `/panel` просит подождать пару секунд; при
  ошибке остаётся inline-резерв.

  Для стабильного адреса задайте свой HTTPS reverse proxy или именованный
  туннель в `telegram.web_app_url` — тогда автоматический туннель не
  запускается. Если Telegram пишет «domain not allowed», добавьте домен
  боту в BotFather (`/setdomain` или Configure Mini App).

  Бесплатный вариант без своего домена — **Tailscale Funnel**:

  ```text
  tailscale funnel --bg --https=443 8765
  tailscale funnel status
  ```

  Он даёт постоянный `https://<machine>.<tailnet>.ts.net`, не показывает
  предупреждающих страниц и работает как служба Tailscale. Пропишите этот
  адрес в `telegram.web_app_url`, а `telegram.web_app_tunnel` установите
  в `false` — тогда бот не будет поднимать Cloudflare/ngrok. Для первого
  запуска нужен аккаунт Tailscale; Funnel включается по ссылке, которую
  печатает команда.

  Бесплатный ngrok тоже даёт постоянный `*.ngrok-free.dev`, но подменяет
  первый браузерный запрос страницей `ERR_NGROK_6024`. Telegram WebView
  не умеет отправлять обходной заголовок, поэтому для Mini App этот вариант
  без платного тарифа не подходит.

  Каждый API-запрос проверяет подпись Telegram `initData` и ID из
  `telegram.allowed_users`; без этой подписи настройки недоступны.

  HTML, CSS и JavaScript страницы лежат в `nemus/core/webapp/index.html`.
  Файл читается при каждом запросе: после правки разметки достаточно
  перезагрузить Mini App. Новые API-методы (каталог моделей, Hugging Face)
  живут в процессе бота, поэтому после обновления кода бота нужно
  перезапустить. Если открыть HTML в обычном браузере, показывается
  предпросмотр дизайна с демо-данными без доступа к настройкам.
- **Ephemeral в группах.** Информационные ответы на кнопки («Статус»,
  «Помощь», «Примеры», «Скиллы», подтверждение нового диалога) видит только
  нажавший. Если сервер не поддерживает ephemeral, бот отвечает всплывающим
  alert'ом и не засоряет группу.

В группах бот отвечает только на сообщения, где его упомянули через
`@username`, или на reply на своё сообщение. Иначе при `allow_groups` он
реагировал бы на каждую реплику владельца и засорял разговор. Ephemeral
включается `advanced_ui`; панель и черновики доступны только в личке.

Что не входит: TON Wallet, платежи, shared widgets, виджеты и черновики в
группах, inline-режим.

## Безопасность

- `telegram.allowed_users` обязателен: без него бот не запускается.
- Скачанные вложения лежат в `<workspace>/telegram/<chat_id>`; файлы старше
  7 дней или сверх 500 на чат удаляются автоматически. Имена уникальны, поэтому
  альбом из одинаковых `photo.jpg` ничего не перезаписывает.
- Токен и API-ключи не коммить. Старый `data/workspace/telegram_bridge.py`
  содержал токен в открытом виде — удали его и перевыпусти токен у @BotFather,
  если он ещё где-то лежит.
- Бот выполняет команды на хосте с правами своего пользователя. На VPS не
  запускай его от root: создай отдельного пользователя и рабочую папку.
