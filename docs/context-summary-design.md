# Автоматическая выжимка контекста

## Проблема

Сейчас `Agent._history_for_model()` при переполнении `tools.max_history_chars`
просто выбрасывает старые сообщения. System-промпт, инструменты и скиллы
остаются, но модель теряет нить задачи: приходится открывать новый чат и
объяснять всё заново.

Дополнительно:

- после перезапуска GUI подгружаются только 20 последних сообщений;
- у Telegram-агента сейчас `memory=None`, поэтому его история вообще не
  переживает перезапуск.

## Цель

При приближении к лимиту контекста автоматически сжимать старую часть диалога
в компактную выжимку и продолжать разговор в том же чате.

При этом **не** заменять и **не** сокращать:

- system-промпт;
- список инструментов и их схемы;
- инструкции скиллов;
- текущую задачу и последние сообщения.

Выжимка — дополнительный блок памяти, а не замена системного промпта.

## Поведение

### Когда срабатывает

Когда суммарный размер истории (без system-промпта) превышает
`tools.max_history_chars`. До этого сообщения уходят как есть.

### Что сжимается

Старая часть диалога, которая вот-вот выпадет из окна. Последние сообщения
остаются дословно. Граница выбирается по ходу пользователя, чтобы не разрывать
пары `assistant.tool_calls → tool`.

Повторно весь чат не суммируется: новая выжимка = предыдущая выжимка + новые
сообщения, которые выпадают. Так стоимость не растёт с каждым переполнением.

### Что попадает в выжимку

- цель и текущая задача;
- договорённости и решения;
- факты о пользователе и его предпочтения;
- выполненные действия и результаты;
- незавершённые шаги и что делать дальше;
- важные пути, команды, имена файлов, ошибки и ограничения.

Не попадают: полный список инструментов, текст system-промпта, инструкции
скиллов. Они и так остаются в запросе.

### Как отправляется модели

На каждый запрос:

```
[полный system prompt + скиллы + схемы инструментов]
[выжимка предыдущей части диалога]
[последние сообщения без изменений]
```

Выжимка добавляется в system-сообщение **только для запроса** и не мутирует
сохранённый system-промпт. При пересборке промпта (`_refresh_system_prompt`)
она не теряется, потому что хранится отдельно.

### Ошибка выжимки

Если отдельный запрос к LLM не удался, чат не ломается: используется текущая
обрезка истории. В лог пишется предупреждение.

## Хранение

### GUI и обычные сессии

В SQLite добавляется таблица:

```sql
CREATE TABLE IF NOT EXISTS session_summaries (
    session_id INTEGER PRIMARY KEY,
    summary TEXT NOT NULL,
    covered_until INTEGER NOT NULL DEFAULT 0,
    updated_at TEXT NOT NULL
);
```

`covered_until` — id последнего сообщения, вошедшего в выжимку. При загрузке
сессии агент берёт выжимку и сообщения после `covered_until`, а не только
последние 20.

Выжимка очищается при:

- `clear_messages()` — очистка текущего диалога;
- `delete_session()` — удаление диалога;
- создании нового диалога;
- `Agent.reset()`.

### Telegram

Telegram получает отдельную базу `telegram.db` рядом с основной, чтобы не
смешивать диалоги с GUI и не зависеть от глобального `current_session_id`
основной памяти.

- В `Core` появляется ленивое хранилище `telegram_memory`.
- У каждого Telegram-чата своя сессия.
- Соответствие `chat_id → session_id` хранится в таблице `meta` этой базы.
- Перед каждой задачей бот переключает агента на сессию нужного чата.
- `/new` создаёт новую сессию только для этого чата.
- После перезапуска бота сессия, история и выжимка восстанавливаются.

## Настройки

Добавляется `tools.max_summary_chars` (по умолчанию `4000`) — максимальный
размер выжимки. Фактический лимит выжимки — `min(max_summary_chars,
max_history_chars // 4)`, чтобы она не съедала весь бюджет даже при маленьких
тестовых значениях. Остальной бюджет остаётся у последних сообщений.

## Тесты

1. Переполнение вызывает выжимку, system-промпт остаётся первым и полным.
2. В запросе есть выжимка и последние сообщения; старые сообщения не уходят.
3. Повторное переполнение обновляет выжимку, а не суммирует всё заново.
4. Выжимка сохраняется в SQLite и восстанавливается после перезапуска.
5. Загрузка сессии берёт сообщения после `covered_until`.
6. Ошибка LLM при выжимке откатывается на обычную обрезку.
7. `clear_messages`, `delete_session`, `reset` и новый диалог очищают выжимку.
8. Telegram: разные чаты получают разные сессии; `/new` не трогает соседний
   чат; после перезапуска история и выжимка восстанавливаются.
9. Существующие тесты `test_context_budget.py`, `test_sessions.py`,
   `test_history.py`, `test_telegram.py` остаются зелёными.

## Риски и ограничения

- Выжимка — дополнительный запрос к LLM, поэтому при переполнении ответ может
  задержаться. Запрос ограничен по времени и не повторяется бесконечно.
- Выжимка может потерять малозначимую деталь. Поэтому она дополняется
  последними сообщениями, а не заменяет их.
- Telegram получает отдельную БД; это осознанно, чтобы не пересекаться с GUI.
- Реальные Telegram и Docker в этом изменении не проверяются.
